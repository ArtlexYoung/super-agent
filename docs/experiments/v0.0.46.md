# v0.0.46 Planning and Evolution Proof

This experiment verifies that task planning, per-step routing, Planner evolution, and model routing evolution use the normal Runtime path. It is a deterministic mechanism proof, not a benchmark of model answer quality.

## Reproduce

From the repository root at tag `v0.0.46`:

```bash
PYTHONPATH=src python3 docs/experiments/run_v0_0_46.py \
  --output docs/experiments/v0.0.46.json
```

The script uses temporary JSONL storage and deterministic local Providers. It requires no network access, API key, optional dependency, or persistent database. The report excludes temporary paths, run IDs, evolution IDs, candidate IDs, timestamps, latency values, and generated content hashes, so identical proof inputs produce identical JSON.

## What Is Checked

- A complex task progressively discloses `planner:default` and creates two validated steps.
- Each step returns to `AdaptiveTaskLoop` and independently routes by its declared purpose: research uses `model:fast`, synthesis uses `model:deep`.
- A named `researcher` subagent runs only for its selected step and its result returns to that step.
- Planner and both selected model Skills receive ordinary `agent_run` evaluation records.
- An Agent-owned Planner Skill turns a real invalid-plan failure into an automatic recommendation, complete-directory candidate, evaluation, and promoted `0.1.1` revision.
- An Agent-owned model Skill follows the same state machine after a real Provider failure.
- Model evolution improves routing metadata while preserving the user-owned provider, model identifier, and connection-update permission.

## Shared State Machine

Planner and model evolution both emit the same canonical event sequence:

```text
skill_evolution.started
skill_evolution.candidate_created
skill_evolution.candidate_evaluated
skill_evolution.candidate_promoted
```

Both states have `origin = automatic`, use failed `agent_run` records as evidence, receive evaluation score `1.0`, and promote from `0.1.0` to `0.1.1`. There is no Planner-specific or model-specific evolution controller.

## Committed Result

All seven checks passed. The planned task completed both steps and returned `final answer`. The Planner and model proofs each evaluated `model:main`, `planner:default`, and `workflow:direct` on the failure run, but only the explicitly Agent-owned updateable target evolved. The committed [JSON report](v0.0.46.json) is the machine-readable result; its `input_sha256` covers the prompts, Planner revisions, and declared planning model traits.
