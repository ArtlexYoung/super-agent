# v0.0.34 Local Experiment

This experiment checks whether the central Skill-first lifecycle works as one connected system. It is a mechanism proof, not a claim about model answer quality or production throughput.

## Reproduce

From the repository root at tag `v0.0.34`:

```bash
PYTHONPATH=src python3 -c 'from cli import main; raise SystemExit(main(["benchmark", "--config", "examples/basic/agent.toml", "--cases", "examples/basic/benchmark-cases.json", "--output", "docs/experiments/v0.0.34.json"]))'
```

The command uses only the Python standard library for JSONL and SQLite. To include disposable remote databases, install the matching optional driver and set `SUPER_AGENT_TEST_MYSQL_URL` or `SUPER_AGENT_TEST_POSTGRESQL_URL`. These environments are intentionally separate from normal Agent storage configuration.

## What Is Checked

- Context comparison uses the same system prompt and user prompt in `no_skill`, `eager_skill`, and `progressive_skill` modes. Eager and progressive modes share the compact Runtime index; only loaded Skill content differs.
- Discovery and disclosure use the central `ProgressiveDisclosureCore`.
- Execution uses the normal `Agent` and `AgentRuntime` path and records canonical run evaluations.
- Evolution creates a complete-directory candidate, evaluates it, promotes `0.1.0` to `0.1.1`, and rolls back to `0.1.0`.
- Storage verification repeats the same conversation, memory, Skill-habit, user, and Agent isolation checks on every available backend, then verifies cleanup.

## Reading The Report

The committed [JSON report](v0.0.34.json) contains no absolute workspace paths, run IDs, candidate IDs, database URLs, or secrets. `input_sha256` stays stable while cases, system prompt, Skill contents, fixture, and selected backends are unchanged. Phase durations are measurements from the generating machine and are expected to change.

Context tokens use `ceil(character count / 4)` so the experiment remains dependency-free and repeatable. This is a consistent comparison metric, not an exact tokenizer result. The deterministic Provider proves lifecycle wiring and rollback behavior; evaluating real model quality requires project-specific cases and a real Provider.

## Committed Result

The committed run passed all seven lifecycle checks. Across the two example cases, eager Skill context used 379 estimated tokens, progressive Skill context used 330, and no-Skill context used 33. Progressive disclosure saved 49 tokens, or 12.93%, relative to eager loading for this small Skill tree.

JSONL and SQLite passed every isolation and cleanup check. MySQL and PostgreSQL are recorded as `unavailable` because their disposable test database environments were not configured; `all_backends_verified` is therefore `false`, while `all_available_backends_passed` is `true`. This distinction prevents missing infrastructure from being reported as successful verification.
