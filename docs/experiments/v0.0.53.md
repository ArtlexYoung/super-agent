# v0.0.53 Compact End-to-End Runtime Proof

This experiment verifies the complete safety, memory, transport, evaluation, and
evolution loop through one real Runtime path. It uses only the Python standard library,
a deterministic local Provider, and temporary files.

## Run

From the repository root:

```bash
PYTHONPATH=src python3 docs/experiments/run_v0_0_53.py
```

The command rewrites [v0.0.53.json](v0.0.53.json). Running it repeatedly with the same
source produces the same report bytes.

## Executed Path

The script starts the real `AGUIHTTPServer` on an ephemeral local port and sends one
HTTP request to `/ag-ui`:

```text
AG-UI HTTP/SSE request
  -> Agent.run
  -> AgentRuntime.run_task
  -> recall-time memory organization
  -> AdaptiveTaskLoop
  -> registered external SkillRunner Tool
  -> Runtime Safety blocks execute + network
  -> failed task evaluation
  -> automatic Skill candidate, evaluation, and promotion
  -> canonical run.failed event
  -> AG-UI RUN_ERROR
```

The custom `external:protected` Skill contains only declarative content. Its Tool exists
only because the application explicitly registers an external `SkillRunner` in code.
The Tool handler increments a probe if called, which makes pre-execution blocking
directly observable.

## Result

All five checks pass:

| Check | Evidence |
| --- | --- |
| Recall organizes and forgets | Two relevant memories become one active current fact; organization start, forget, and completion events remain in history. |
| Safety blocks before execution | The action declares `execute` and `network`, receives `require_confirmation`, and the handler call count remains zero. |
| AG-UI streams the canonical error | The same live stream contains Runtime `CUSTOM` events, Tool events, and terminal `RUN_ERROR` with `ActionConfirmationRequired`. |
| Failure evolves an owned Skill | `external:protected` follows started, candidate-created, evaluated, and promoted states, then becomes `0.1.1`. |
| Provider purposes stay centralized | One Provider serves memory organization, the task, Skill evolution, and Skill evaluation through Runtime model routing. |

`2cbcbb024d3a7059af8d25809d85e2029ed8b89881106950250f11a238ee38e5`.

## Scope

This proof tests Runtime contracts, not remote model quality. It intentionally does not
test production authentication, TLS, an approval user interface, or a third-party model
API. Those concerns remain deployment and integration tests; they are not replaced by a
deterministic local experiment.
