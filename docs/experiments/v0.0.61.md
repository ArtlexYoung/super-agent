# v0.0.61 Unified Multiuser Runtime Proof

This proof runs the current public Agent API through one deterministic, dependency-free
multiuser scenario. It uses temporary JSONL storage and a local standard-library HTTP
model fixture. It does not call an external service or require an API key.

## Run

From the repository root:

```bash
PYTHONPATH=src python3 docs/experiments/run_v0_0_61.py
```

The command rewrites [v0.0.61.json](v0.0.61.json). Repeated runs with the same source
produce identical report bytes. The report omits temporary paths, ports, timestamps,
latency, generated IDs, and credential values.

## Executed Path

One `Agent` receives two user-scoped model Skill overlays. Alice and Bob use the same
model profile keys, connection, and credential variable name, but different model
descriptions and credential values.

```text
Alice
  -> user model Skills select specialist from declared task traits
  -> recall organizes two memories and forgets the stale item
  -> external Tool declares execute + network
  -> Runtime Safety blocks before the handler
  -> failed-run evaluation recommends Skill evolution
  -> candidate is created, evaluated, and promoted to Alice's overlay

Bob
  -> user model Skills select general from declared task traits
  -> isolated memory and conversation remain private
  -> task completes without seeing Alice's evolved Skill or credential
```

Every step above uses the shipped progressive disclosure core, `AgentRuntime`, adaptive
task loop, action executor, event store, memory Capability, and evolution state machine.
The proof fixture supplies deterministic model responses only; it does not implement a
second scheduler or execution engine.

## Result

All seven checks pass:

| Check | Evidence |
| --- | --- |
| User model and credential isolation | Alice selects `alice-specialist-model`; Bob selects `bob-general-model`; the shared credential variable resolves separately. |
| Automatic model scheduling | The same Runtime derives `external_operation` for Alice and `answer` for Bob, then selects profiles from declared traits. |
| Progressive disclosure isolation | Both users reuse cached disclosure paths, and every path stays below that user's private cache root. |
| Memory organization and forgetting | Alice's stale fact leaves the active view through organization events; Bob's memory is unchanged. |
| Mandatory Safety | `execute` plus `network` records `action.checked` and `action.blocked`; the Tool handler call count remains zero. |
| User-only evolution | Alice receives `external:protected@0.1.1`; Bob and the shared project Skill remain at `0.1.0`. |
| Canonical state without secrets | Alice ends with `run.failed`, Bob with `run.completed`, both locks report ready models, and no credential value enters events, locks, or files. |

The report input hash is
`61e38c9c3acc4d7601fd28654e39927d3213fa38a8fc74434f0448964f98bafe`.

## Scope

This is a mechanism and isolation proof, not a model-quality or production-load
benchmark. Authentication, TLS, remote database operations, and third-party model
behavior remain deployment-specific integration concerns.
