# T0：任务样本与离线执行基线

日期：2026-09-11。范围：新产品计划的 T0，版本保持 0.2.105。状态：离线样本、反例与基线已完成；真实模型基线未验证。

## 目标与约束

固定两个输入和独立验收方式，为后续提交、检视、退回和交付提供可运行样本。复用 `Agent`、`MockModel`、`CodeWorkspace`、中央工具执行器及现有插件；不新增运行器、队列或场景协议。

所有样本、检查与脚本位于本目录；生成结果位于忽略的 `tests/eval/reports/`。仅本目录受控文件显式纳入 Git，不添加整个评测目录。不得修改既有数据集、凭证、模型配置、依赖、产品实现和版本。Python 使用 Homebrew 3.11。

## 样本与验收

| 样本 | 输入和修改范围 | 产物 | 外部检查 |
| --- | --- | --- | --- |
| bug-fix | 时间窗口筛选的边界错误；只修改 event_window.py | 修复后的模块 | 独立进程检查半开区间、空集、顺序、不变性；原始缺陷必须失败 |
| research | 固定 Python JSON / SQLite WAL 官方资料与本机单写者约束；只创建 decision.json | 结构化选择和事实引用 | 核对已知事实、反例、来源关系与禁止声称的结论；资料不得修改 |

资料为短摘录，2026-09-11 核对官方 URL 后冻结，不宣称完整网页快照。研究验收仅覆盖固定事实集，不评价开放问题的推理质量，也不把 JSON 缺少分帧误当成 JSONL 不可用。

每次在独立临时工作区执行；评价器留在工作区外。受控样本不是恶意代码沙箱，不可直接用于运行不受信任的外部补丁。记录输入、评价器、产物、产品源码和方法文件的 SHA-256；既有输出目录拒绝覆盖。

## 对照、预算与证据

- 普通 Agent、显式启用单个 code/research Skill、完整插件三条路径，各执行相同已知答案的三次工具调用：读取、写入、回读；第四次模型响应返回。
- 脚本化响应仅校验链路和输入体积，不证明自动选场景、自动修复、研究能力、多 Agent 收益或真实模型 token / 费用。
- 网络模型调用预算为 0。运行基线不访问网络；官方资料核对单独进行。记录模型请求数、UTF-8 JSON 请求字节、工具与事件数、耗时；不把单次墙钟时间作为性能结论。
- 负例：仅口头宣称完成、错误/缺失引用、越界改动、旧产物验收、并发编辑后的过期写入、拒绝写入、执行前取消、运行中取消。取消使用事件同步，不靠 sleep 猜测时序。
- 检查当前队列 completed 的含义；记录运行中取消实际行为，T0 不伪造新的验收/停止状态。

## 验证与接续

T1 可复用这些检查建立产品闭环；真实模型基线仍需明确模型和预算，不能用固定答案代替。这里仅有两个受控微型样本，没有真实用户项目、开放式研究或完整 CLI 使用旅程的效果证据。

2026-09-11 首次试跑：完整 code 插件经 common/team 依赖要求团队工具，单 Agent 文件工具装配在调用模型前失败。加入独立 Skill 对照并保存完整插件失败，不临时挂空团队、不静默退化。此问题交给后续场景依赖整理，失败不计为通过。

### 真实模型任务闭环验证（v0.2.122 后补做）

用 `real_task_loop.py` 走 v0.2.113 的任务闭环，端点与密钥只从环境变量读取。报告目录
`tests/eval/reports/real-task-loop-20260911-v02122`（被忽略）。

| 路线 | 结果 | 模型调用 | 工具调用 | 耗时 | token 入/出 | 费用 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| Python 组合（execute/submit/check/deliver） | 交付成功，结论 `passed` | 9 | 10 | 120.3s | 63,008 / 3,149 | $0.0662 |
| CLI `/task new/run/submit/check/deliver` | 五步全通过，交付成功 | 9 | 11 | 113.0s | 65,899 / 3,014 | $0.0689 |
| 反例对照（产物未修复） | 检查 `failed`，交付被拒绝 | 1 | — | — | 3,180 / 556 | $0.0037 |

合计 19 次模型调用、132,087 / 6,719 token、$0.1388，仍在要求的小规模范围内。

关键结论：**运行 `completed` 不等于任务已交付**。反例对照里任务状态为 `completed`，但检查
结论 `failed`、`stage=needs_attention`，交付被拒绝并给出 `delivery requires current accepted
artifacts and criteria` —— 这正是 v0.2.113 想区分的两件事。

过程中发现并修复的真实缺陷：验证脚本首次运行时 `code.toml` 只声明了 `execute`，`write` 仍为
默认的 `ask`，导致模型调用 `replace_in_file` 被 `ToolPolicy` 拒绝（`tool effects are not
allowed`）。这是宿主授权声明不完整，不是产品缺陷；补齐后两条路线都交付成功。该次失败记录
保留为"权限未声明时副作用被拦下"的真实证据。

仍未验证：真实模型只跑了各 1 次，不能作为能力、稳定性或费用比较；多人检视、依赖返工、
取消与恢复均未接入真实模型。

### 确认的边界与后续

- 子 Agent 仅声称“修好”即被队列记为 completed，而原始缺陷仍无法通过外部测试。T1 必须区分运行结束和成果验收。
- created/queued 取消不会调用对应模型；running 取消抛出 `running -> cancelled`。没有“已取消但还在执行”的成功声明，也尚未实现运行中停止。T3 要补停止、迟到结果与恢复语义。
- 拒绝写入、过期文件 SHA-256 均保留原文件；动作事件有 `(run_id, call_id)` 可关联。这不是跨重试操作幂等身份，未测试外部副作用的未知结果重放，不宣称恰好一次。
- 技能/资源输入开销为 E2 的定位信号；完整编码插件依赖问题已在 v0.2.114 修复并由六条全通过路径记录。
- 真实模型验证（v0.2.114）见 `development-plan/v0.2.114/PLAN.md` 与 `tests/eval/reports/real-model-20260911-v02114`：缺陷修复任务通过独立验收；调研任务事实与出处全部正确，但固定样本要求顶层键恰好为三项而模型多写了说明字段，因此记为未通过，未修改样本。
- 检查记录绑定产物与评价器摘要；这只是测试工具，尚未接入产品的提交、验收、退回、交付或持久化状态。
